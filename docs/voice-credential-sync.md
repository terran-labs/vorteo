# Shared Voice credentials

In an installation, the installation secret authority owns Voice OpenAI keys and endpoints. A save commits every changed speech site in one revision-checked request before the app switches any provider. The editor freezes expected revisions when it opens, so background polls cannot refresh a stale edit's version. Concurrent stale saves fail with the existing settings conflict message. Environments receive the resulting records asynchronously and report pending delivery until they apply them.

Existing persisted or process-environment keys are adopted once through an authenticated, nonce-bound push. A base URL is eligible for adoption only beside a key from the same environment. Conflicting pairs are withheld until the owner saves a choice. After adoption the authority's copy is delivered to all environments; delivery never persists unrelated process-environment fallbacks.

A new key uses `https://api.openai.com/v1` unless its save explicitly includes an endpoint. The app does not carry an old shared endpoint into a key-only edit. Both owner writes and adoption pushes validate endpoint URLs: HTTPS is accepted generally. HTTP is accepted only for `localhost`, literal IPv4 loopback or RFC1918 addresses, and IPv6 loopback or ULA addresses. This supports local OpenAI-compatible servers without allowing plaintext credentials to public hosts. Private HTTP still trusts the local network. Arbitrary DNS names are not treated as private. URL user information, fragments, control characters and oversized values are rejected.

Only configured or explicitly cleared authority records disable process-environment key fallback. Empty never-configured sites and conflicted deliveries do not write credential fields or set that marker. Withdrawal releases the marker without persisting fallback values. On standalone startup the daemon removes stale markers, and standalone speech resolution ignores them even before the next write. Unbinding takes effect when the daemon starts with an unbound configuration; the settings API continues to reject removal of an installation binding.

Speech delivery generations follow credential revisions, so unrelated installation settings do not cause credential rewrites. The delivery recipient still verifies its current installation and server identity through fresh admission. Adoption additionally verifies the settings revision, a ten-second nonce, the authenticated role and its configured server identity; accepting or finishing a nonce consumes it. The current installation config assigns a distinct role token to its one Host and one Dev server. An owner cookie never authenticates an agent push.

Ordinary provider-key readiness keeps its previous behavior. Speech readiness additionally requires no adoption conflict. A standalone daemon continues to save Voice keys locally. Rollout requires the coordinator and every environment to advertise speech-secret support; the app asks for a coordinator update when an older owner API rejects a speech request.

## Rolling updates

Updating a Host before its coordinator preserves existing transcription credentials. The Host advertises `speechSecretDelivery` and passively accepts authenticated deliveries; it does not initiate adoption or clear keys on a timer. Until a speech-capable coordinator requests adoption, the persisted key and ordinary environment fallback remain available, and no speech journal or authority record is created. The old coordinator only synchronizes provider `env` keys.

Credential edits are deliberately blocked during this interval. An older interface cannot replace a Voice key through the local settings RPC while the Host belongs to an installation. The new interface asks for a coordinator update when speech metadata or writes are unsupported. Non-secret Voice settings remain editable. Update the coordinator before changing keys; do not add a local-write fallback that creates competing installation credentials. This mixed-version interval is safe for existing transcription, but does not provide shared credential editing until the coordinator is updated.
