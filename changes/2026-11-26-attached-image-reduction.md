### Fixes

- Large images are now made smaller when you attach them, so ordinary screenshots fit in a message. Images picked, pasted or dropped into the composer, or added to a queued message, are scaled to at most 2,576 pixels on the long edge and 3 MiB each. Transparent images stay PNG; others become JPEG when that is smaller. Small images, GIFs and other files are unchanged.

## Maintenance review

Issue #679, second part. `reduceImageForSending` in the app's attachment utilities takes an `ImageCodec` port and decides size and format; `attachments/image-codec.ts` implements it for web and desktop with `createImageBitmap` and a canvas (reading a desktop path through the existing desktop file reader), and `image-codec.native.ts` with `expo-image-manipulator`, writing a pasted data URL to a scratch file first. The web codec does not use the manipulator because its web resize is a per-pixel JavaScript filter on the main thread, which would stall the page for seconds on a large photo. `persistAttachmentFromBlob`, `persistAttachmentFromDataUrl` and `persistAttachmentFromFileUri`, through which every composer image path (picker, paste, drop, browser element screenshots, legacy draft migration) persists, now reduce first, and the queued message editor reduces before its own store saves. `persistAttachmentFromBytes`, used for file and markdown previews, is unchanged. Limits come from the providers' documentation: Claude downscales beyond 2,576 px and accepts 5 MB per image on Bedrock and Vertex, OpenAI's high detail fits 2,048 px. Not verified: a run on a device or in a browser; the native codec is typechecked only, and transparency is not detected on native, so an opaque PNG there stays PNG and is scaled further instead. Images already attached in a draft are not reduced. One case in the attachment utilities suite reduces a fake 5120 by 2880, 14.9 MB screenshot under both limits and leaves a small one untouched. The attachment store section of the data model and a new inventory entry are updated. README overview and onboarding are unchanged. Not installed; interface only.
