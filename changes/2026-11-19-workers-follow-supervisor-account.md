### Fixes

- A supervisor moved to another account of the same provider can start workers again. The worker account in a preset is now a default: a worker launch that names the configured preset may run on the preset's account or on the supervisor's current account of the same provider type. Another provider type, a third account and a different preset are still refused.
- `switch_agent_profile` accepts `account/model` as its target, the form `create_agent` uses, so an agent can choose the model when it switches a thread. The whole value was previously treated as an account name, so the switch was refused as a different provider.
- Refused worker launches and refused account switches are now written to the daemon log with the caller, the requested account and preset, and a refusal code.

## Maintenance review

A supervisor's frozen worker snapshot names one account. After the owner moved supervisors from an exhausted account to another account of the same type, every worker launch failed: the preset's account no longer matched the requested one, and omitting the preset is refused. Dispatch now accepts the supervisor's current account when it and the preset's account resolve to one provider type in the daemon's provider settings and the caller asks for it, and runs the unchanged preset there. It does not check that the supervisor moved, so a same-type worker account is advisory, as the direction for #518 intends. The preset id, model, reasoning, features, instructions, worker limit, environment exclusions, installation account policy and the quota check on the account used are enforced as before; unknown or unrelated accounts keep the old refusal. Permission mode was never frozen, because a launch may name another mode; that is unchanged here and belongs to #518. The supervisor's stored snapshot is not rewritten. The switch tool passed `account/model` unsplit, which resolved to no provider family and produced "belongs to another account" with a preset and "incompatible target" without one; it now splits the value and passes the model. Tests extend the managed-worker creation suite and the switch tool test; the new assertions fail without the change. Documented in the preset guide. README overview and onboarding are unchanged. Not installed.
