### Fixes

- A supervisor moved to another account of the same provider can start workers again: a worker launch that names the configured preset and the supervisor's current account now runs the frozen preset on that account. Another provider type, a third account and a different preset are still refused.
- `switch_agent_profile` accepts `account/model` as its target, the form `create_agent` uses. The whole value was previously treated as an account name, so the switch was refused as a different provider.
- Refused worker launches and refused account switches are now written to the daemon log with the caller, the requested account and preset, and the reason.

## Maintenance review

A supervisor's frozen worker snapshot names one account. After the owner moved supervisors from an exhausted account to another account of the same type, every worker launch failed: the preset's account no longer matched the requested one, and omitting the preset is refused. Dispatch now compares the supervisor's current account with the preset's and, when both resolve to one provider type in the daemon's provider settings and the caller asks for the current account, runs the unchanged preset there. The preset id, model, mode, features, instructions, worker limit, environment exclusions, installation account policy and the quota check on the account used are enforced as before; unknown or unrelated accounts keep the old refusal. The supervisor's stored snapshot is not rewritten. New supervisors are told that workers run on their current account. The switch tool passed `account/model` unsplit, which resolved to no provider family and produced "belongs to another account" with a preset and "incompatible target" without one; it now splits the value and passes the model. Tests extend the managed-worker creation suite with one case each for following, cross-type, third account, quota and preset mismatch, and the switch tool test with an `account/model` target; both new assertions fail without the change. Documented in the preset guide. README overview and onboarding are unchanged. Not installed.
