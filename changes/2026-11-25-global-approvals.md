## Maintenance review

Issue #659, part C. The daemon records each thread's creator as `createdByAgentId` only from `create_agent`'s authenticated caller, never from labels; a create without an agent caller records none. Later label edits never change it, no snapshot or record write can replace it,. A thread nobody created, or created before this change, stores no creator, so existing records are unchanged and their approvals go to the owner. Snapshots carry it behind the new `agentCreatedBy` capability; older hosts show no approvals on the card, as before. An approval surfaces when the thread has no creator, when its creator holds no finish subscription for it (`permissionWatchedByCreator`, from the finish subscriptions), or when no ancestor up its creator chain can answer (closed, archived, missing, unwatching, or itself waiting on an approval). The daemon flags an approval still pending after 3 minutes (`metadata.ownerEscalated`, timed on the daemon) so it reaches the owner regardless. Pending permissions record the timeline position and epoch where they were requested, so Open thread lands on them and a position from a rebuilt timeline is reported as not found. Tests: the routing table (including an unwatched creator, an escalated approval and a plan approval), the storage rules for the creator, a caller-less create with a parent label recording none, the daemon's request time, watch flag and escalation, and the finish-subscription watch check. Two upstream create_agent expectations gain the recorded creator. No inventory entry changes; README overview and onboarding are unchanged.
