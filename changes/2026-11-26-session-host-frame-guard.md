### Fixes

- A message whose attached images are too large for the session host no longer ends the turn that is running, or every other hosted turn on the connection, with "Session host frame is too large." The daemon now measures the message before sending it and refuses only that message, shown once beside the composer with the draft restored: "These attachments are too large to send together (36 MB; the limit is 32 MB). ## Maintenance review

Issue #679. The session host client measures every frame with `serializeSessionHostFrame` before writing and throws `SessionHostFrameTooLargeError` (code `frame_too_large`, with the measured frame and the limit) without writing, removing only that request from pending, so the connection and its channels stay up. The host, its protocol and its 32 MiB limit are unchanged, so this works against the installed host. `AgentSession` gains an optional `assertPromptFits`, implemented by hosted sessions by measuring the exact `startTurn` frame and forwarded by the provider registry wrapper; the agent manager calls it in `streamAgent`, `replaceAgentRun`, `steerOrReplaceActiveTurn` and `startQueuedMessageNow` before any run is reserved or any turn cancelled, so a refused message never interrupts the turn it would have replaced and a refused steer never falls back to a replacement. If the client still refuses a start (the backstop), `startPendingForegroundTurn` settles the start as failed without recording the attempt or a failed turn, so no "[System Error]" message is appended. Queue delivery settles a size refusal as failed with its reason rather than uncertain, so it is never retried unchanged and needs no history read; failed items already wait for the owner's retry or discard.
