### Fixes

- Claude subscription sign-ins are no longer put at risk by the model list check. Vorteo starts a short Claude Code process to list an account's models and stops it as soon as it answers. Close to the sign-in's eight hour expiry that process also began renewing the sign-in, and stopping it midway could discard the renewed sign-in and sign the account out. Vorteo now skips the check in the last ten minutes before expiry and reuses the last answer, and it reuses a fresh answer for ten minutes instead of starting a process on every catalog refresh.
- An account whose access has expired but which can still renew is no longer reported as signed out. Its next agent session starts and renews the sign-in.

## Maintenance review

Claude model discovery (`model-discovery.ts`) reads the account's stored expiry before starting a CLI for a full sign-in account and starts none within ten minutes of expiry or after it; unreadable storage keeps the earlier behavior. An explicit provider refresh skips the ten minute answer reuse but never the expiry guard. `requireFullSignIn` accepts an expired grant that still holds a refresh token; access-only copies still need a live access token. Evidence from 2026-11-13 captures on the lab Host: the daemon started a discovery CLI per account about every five seconds, each force-killed after answering; a controlled CLI inside the renewal window made exactly one token request, 7.8 s after start, and one earlier controlled run was rejected with a spent refresh token while its stored sign-in was untouched. The link between a killed discovery process and the spent token is inferred from that evidence, not observed directly. The subscription accounts entry in the customizations inventory gains this limitation and guard. Focused tests cover both changes. README overview and onboarding are unchanged. Not installed; acceptance needs both accounts to renew unattended through three consecutive expiry windows.
