### Fixes

- The Claude provider diagnostic no longer risks signing a subscription account out. It runs `claude auth status` with a five second limit, and close to the sign-in's expiry that command could begin renewing the sign-in and be stopped midway. Inside the last ten minutes before expiry, and after it, the diagnostic now reports that the sign-in was not checked instead of running the command.
- Vorteo starts far fewer Claude Code processes to list models. Every client reconnect forced a fresh model list, which on a busy installation started a process per account every five seconds. A forced refresh now reuses an answer less than a minute old, and a failed check is not retried within a minute.

## Maintenance review

`claudeRenewalDue` is the one check shared by model discovery and the provider diagnostic (`getDiagnostic` in `agent.ts`). Whether `claude auth status` itself renews a sign-in was not determined; the diagnostic is guarded regardless. Discovery keeps a failed probe's error for one minute and rethrows it without starting a CLI, except when the refresh was canceled. Process sampling on the lab Host on 2026-11-13 identified the other short-lived Claude Code starts by the daemon as `claude --version` checks, which took no renewal lock in either renewal window and are unchanged. What makes clients reconnect and accounts re-register with the daemon every 20 to 30 seconds is not addressed here; this change only stops that churn from starting a CLI each time. Internal one-shot sessions remain unguarded, as before. Refreshes that overlap, or that are canceled before they answer, still each start a CLI, so the reduction is not a hard limit. A remembered failure or answer can hide a recovery or a new sign-in for up to a minute. For an expired sign-in the diagnostic reports that it was not checked until the next session renews it. Tests cover the one minute reuse under forced refreshes, the failure hold-off with its exemption for a canceled refresh, and the diagnostic skipping `claude auth status` for an expired sign-in while still running it far from expiry; tests clear discovery's remembered answers between cases. The subscription accounts entry in the customizations inventory is updated. README overview and onboarding are unchanged. Not installed.
