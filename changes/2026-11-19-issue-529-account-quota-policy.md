### Maintenance

- Daemons can store an optional account quota policy: per-account pool membership and the share of quota each priority must leave unused. Nothing enforces it yet; launches, account choice, switches and pauses behave as before. Daemons that store it advertise `accountQuotaPolicy`.
- Added a pure floor evaluator that reports whether an account is above or below its floor for a priority, unmeasured, limited or unresolved. Nothing calls it yet.
- Rolling back to a daemon older than this change requires clearing a stored `accountQuotaPolicy` first, because the older daemon refuses to start with it.

## Maintenance review

Issue #529, slice 6 of #518. Added the Account quota floors entry under Incomplete integrations and an Account quota policy section to protocol compatibility. The key and feature are named `accountQuotaPolicy` because `quotaPolicy` already names the schedule quota governor policy. The wire and persisted shape checks only an object with a numeric `version`, so later versions and non-number entries still load; a missing or non-number version stops a daemon, as any invalid config entry does. The daemon accepts a patch only in a strict version 1 shape, refusing unknown fields, with at most 64 accounts and 16 priorities per ladder, account references in the installation provider reference grammar and lowercase priority names, refused before anything is written. A patch that omits the key leaves a stored policy alone, a new policy replaces the old one whole, and `null` clears it. The installation coordinator projects only named keys, so a settings sync preserves a stored policy, which also means each environment keeps its own; shared ownership is still undecided. The evaluator uses the Factory account-choice freshness and lowest-window rules and adds two checks: a reading dated in the future or a remaining percentage outside 0 to 100 is unmeasured. A recorded limit hold or an exhausted window is limited whatever the policy says; otherwise a policy of another version, or a version 1 policy that fails the strict shape, is unresolved and never falls through to a weaker floor. Only owner sessions can patch the policy, but an agent with a shell as the daemon user can edit the config file, so the policy is not a restraint on such agents. Tests extend the protocol wire compatibility suite and the daemon config store suite, and add one evaluator case table. README overview and onboarding are unchanged. Not installed.
