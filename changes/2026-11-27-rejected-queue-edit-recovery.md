### Fixes

- When you edit a queued message that has already been sent, the Queue card now says so, with the time it was sent when the conversation shows it, and offers **Send my edit as a new message** or **Discard my edit**. Before, it said only that the change was kept locally and offered no way to send it. The card also says when the message had started sending, was removed in another window or was changed in another window. A queued message can still be sent while you are editing it; holding it is planned.

## Maintenance review

Issue #691, first part, interface only. Outbox edit records gain an optional local `original` (the text and creation time of the message the editor opened), written by the queue edit draft commit; it is not a wire field. Edits the host refuses as `missing`, `delivery_conflict` or `revision_conflict` render a dedicated recovery in the Queue card in place of Could not synchronize, Retry, Keep local copy, Kept locally, Review saved copy and Remove local copy. The sent time is the latest loaded user message in the thread with the original text, created no earlier than the original; it is absent for records saved before this change and when that message is not loaded. A delivery conflict uses the item's `startedAt`, and falls back to the left-the-queue line when the item failed. `QueueOutbox.resendRejectedEdit` queues the edit's text, context, host attachments and local attachments as a new message under a deterministic operation ID, hands its local attachments to the new record, and then removes the edit; discarding leaves the attachments alone when a resend already owns them. Other rejected commands and other edit errors keep their existing controls. One case in the existing queue view suite sends a rejected edit as a new message and fails without the change. The inventory's durable queues entry is updated. README overview and onboarding are unchanged. Not installed.
