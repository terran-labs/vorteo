### Fixes

- Old Host release folders are removed again after an install, and never while something uses them. Cleanup keeps the selected and previous releases, the newest three, every release a running daemon, session host or provider process executes from, and every release a preview broker deployment plan or the broker configuration names. Each install's `retention.json` lists what was removed, kept or skipped.

## Maintenance review

Background release pruning was suspended on 2026-11-11 because a snapshot of references could not exclude a process starting from a release during deletion. Pruning now sets each candidate job folder aside with an atomic rename to `.pruning-<job id>`, which ends every path a new process could start from, and only then reads the evidence a second time. A folder named by that second read is renamed back; a read that fails renames every folder back and skips the cleanup with the reason. Evidence is the release links, coordinator plans, unfinished jobs, the session host receipt, every absolute path in the preview broker configuration and in broker deployment jobs that are neither succeeded nor rejected, and a process listing: working directories and mapped executables from `lsof`, command lines from `ps`, or `/proc` on Linux, for this user's processes. Links are resolved without requiring their target to exist, so a release selected during cleanup still protects its folder while it is set aside.

The session host now derives its release from the path its own code was loaded from, not from the release link, and confirms the release still exists after publishing its receipt. A host whose release was set aside during startup fails that start before serving; launchd starts it again through the release link. A folder whose deletion fails stays set aside and is retried by the next cleanup; previously it stayed at its original path half deleted.

Known limits: processes of other users are not listed, and a failed process listing skips cleanup, so disk use keeps growing until the cause is fixed. A session host started before this change has no post-publication check, though the process listing covers it. Nothing here restores releases that were already removed. Delivery needs a coordinator update for pruning and a tracked session host restart for the startup check. README overview and onboarding are unchanged. Not installed.
