## Maintenance review

The 11-12 Claude 2 lapse could not be explained without Claude Code's own refresh logging, and the earlier `--debug-file` helper was disabled because Vorteo could not hold custody of a path the SDK opens later, nor show that the output excludes credentials. This version passes no path. Claude Code 2.1.321 runs with its supported `--debug-to-stderr`, and Vorteo already owns that stderr through its custom spawn, so the SDK never folds debug text into exit errors. Debug lines (`<ISO time> [LEVEL] …`) are diverted before the daemon log and the in-memory stderr diagnostic. Only lines naming sign-in topics are kept. Lines naming bearer, authorization, cookie or API key material are dropped whole, and every run of 24 or more token-alphabet characters and every email address is replaced, so the filter holds even if the CLI's own masking misses something. Vorteo creates and checks the 0700 directory, refuses symlinks, other owners and open modes, and opens the file itself with O_CREAT, O_EXCL and O_NOFOLLOW at 0600. Lines are capped at 600 characters and files at 8 MiB. Any refusal starts the CLI without debug output. Focused tests cover the account-scoped opt-in, a symlinked directory, and filtering and passthrough across split chunks, using synthetic values only. The obsolete null-path helper and its test are removed. Sessions already running in the session host keep its build until it restarts; daemon-spawned sessions use the new code after a Host update. The durable sessions inventory entry is updated. README overview and onboarding are unchanged.
