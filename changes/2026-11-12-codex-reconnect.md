### Fixes

- Reconnecting an older Codex account now signs it in. With Host-owned Codex sign-in on, every Codex reconnect went to the installation coordinator, which only signs in accounts the installation created, so older accounts never got a new sign-in. Those accounts now sign in through their own daemon, which writes the account's sign-in where its agents read it.
- Settings shows a Codex account as needing reconnection once Codex reports that it could not refresh the stored sign-in. Previously the access token kept answering usage reads, so the account looked connected while every new agent failed.

## Maintenance review

On 11-12 Codex 1 failed hourly with "refresh token has expired", and the owner's reconnect at about 17:05Z did not change its runtime `auth.json`. Installation settings showed that no Codex definition carries an `accountSetup` record, and the coordinator's `codex/signin` routes refuse such definitions, while the app routed every Codex account there whenever `codexHostRefresh` was on. `useSharedInstallationSignIn` now takes the account and asks the settings snapshot: a bound Codex definition without `accountSetup` uses the daemon's device sign-in, whose `openAccountLoginSession` writes the account's configured `CODEX_HOME`. A definition not yet in the snapshot keeps the coordinator route, so newly added installation accounts are unchanged. For Settings, a failed Codex turn whose error or diagnostic matches Codex's refresh-refusal text writes `.vorteo-signin/refresh-rejected.json` in that `CODEX_HOME`. The file holds only `auth.json`'s modification time and size, captured when the failing turn started, and never credential content. A failure that arrives after a reconnect replaced `auth.json` records nothing, so a completed new sign-in is never marked rejected (found in independent review; covered by a race test). The usage reader then reports device-code `authRecovery` without calling the usage API until `auth.json` changes, and the Reconnect dialog opens the sign-in panel. Hosted Codex sessions write the record only once the session host runs this build. Focused tests cover the per-account routing and the record's set-and-clear cycle with synthetic values. The owner must reconnect Codex 1 once after install. The accounts inventory entry is updated. README overview and onboarding are unchanged.
