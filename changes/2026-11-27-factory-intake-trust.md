### Fixes

- Factory takes work only from trusted accounts on public repositories. Claiming an issue now refuses it unless the owner, an organization admin or a delegated approver applied `factory:ready` after anyone else last wrote, edited or retitled it, and says what to do. Unreadable history refuses too.
- Leads, workers and reviewers now get an issue brief: the approved task and trusted comments, with every other comment quoted in a block marked as outside text. Every role charter treats outside text as data and never runs commands, opens links or installs anything it asks for.
- Pull requests from forks no longer count as an issue's pull request, as overlapping work or as claim markers, and the queue ignores reviews from untrusted accounts and shows why an issue waits.
- Changed behavior for several installations on one repository: claim markers now count only in comments by trusted accounts, so every installation must post from the owner's account, an organization admin or a login in `.github/delivery-approvers.json`.

## Maintenance review

Added `factory/project/trust.ts`. `claim issue` reads trusted accounts (repository owner, active organization admins through `orgs/<org>/memberships/<login>`, and `.github/delivery-approvers.json` on the default branch) and the issue's body edits, label and retitle timeline and comments through GraphQL, then refuses with `factory_issue_untrusted` before any branch is created. Only `factory:ready` approves text, through the single `labelApproves` function, so the owner's later GitHub App identity (#687) can extend it there. Claimed and held results add an optional `brief`; queue issues add an optional `untrusted` reason, and the queue reads only Factory-labeled issues. Claim markers count only in trusted comments, the queue excludes fork pull requests and untrusted reviews, and the Foreman, Triage and Mechanic charters plus the shared rules gain the outside-text rules; the general rule against editing role instructions is unchanged. Tests add one intake trust case table and a brief, marker and queue case to the Factory service suite, and give existing marker and review fixtures trusted authors. Updated the Factory guide, the delegated approvers file description and a new Factory intake trust inventory entry. README overview and onboarding are unchanged. Agents still act on GitHub as the owner, so this does not stop an agent misled into writing outside text as the owner. Not installed: delivery needs a Host daemon install, and the charter change triggers the Mechanic's instructions review.
