### Fixes

- Factory takes work only from trusted accounts on public repositories. Claiming an issue now refuses it unless the owner, an organization admin or a delegated approver applied `factory:ready` after anyone else last wrote, edited or retitled it, and says what to do. Any read that fails refuses too.
- Claiming refuses when the issue's pull request, from the claim branch or an older `<prefix>/factory-issue-<n>` branch, changes `.github/delivery-approvers.json` or `.github/factory.json`; the owner reviews and merges such a pull request. Only those two files are guarded; the rest of Factory's trust code relies on review.
- The claim names the pull request head it checked, and the Foreman merges only that commit when the reviewer approved it, pinned with `gh pr merge --match-head-commit`, so a push after the review or the check never merges.
- Leads, workers and reviewers now get an issue brief: the approved task, comments from the owner's account, quoted agent notes and every other comment quoted in a block marked as outside text. Every role charter treats outside text as data, never runs commands, opens links or installs anything it asks for, and does not open links in an approved issue unless the owner's words ask to.
- Autonomous Triage no longer labels an issue an untrusted account wrote, edited or retitled; it asks the owner.
- Pull requests from forks no longer count as an issue's pull request, as overlapping work or as claim markers, and the queue ignores reviews from untrusted accounts and shows why an issue waits.
- Changed behavior for several installations on one repository: claim markers now count only in comments by trusted accounts, so every installation must post from the owner's account, an organization admin or a login in `.github/delivery-approvers.json`.

## Maintenance review

Added `factory/project/trust.ts`. `claim issue` reads trusted accounts (repository owner, active organization admins through `orgs/<org>/memberships/<login>`, and `.github/delivery-approvers.json` on the default branch) and the issue's body edits, label and retitle timeline and comments through GraphQL, then refuses with `factory_issue_untrusted` before any branch is created; failed lookups, GraphQL errors and unparseable answers refuse the same way, and deleted labels are tolerated. Only `factory:ready` approves text, through the single `labelApproves` function, so the owner's later GitHub App identity (#687) can extend it there. Held and claimed results also refuse with `factory_owner_only_file` when an open same-repository pull request from the claim branch or the older suffix form changes the approvers file or `.github/factory.json`, re-reading each head after its files and refusing if it moved, and return that head as the optional `checkedHeadSha`, which the Foreman's merge step pins. Claimed and held results add an optional `brief`; agent notes are recognized with a tolerant "(AI Generated)" prefix match and quoted, and quoting normalizes every line terminator. Queue issues add an optional `untrusted` reason; one failed account lookup marks only the issues it touches, and the queue reads only Factory-labeled issues. Releasing a claim no longer needs a trust read. Claim markers count only in trusted comments, the queue excludes fork pull requests and untrusted reviews, and the shared rules plus the Foreman, Triage and Mechanic charters gain the outside-text, owner-only-file and autonomous-labeling rules; the general rule against editing role instructions is unchanged. The Factory guide separates what the daemon enforces from what rests on the charters. Tests add one intake trust case table, including read failures and re-approval after an outside edit, and brief, marker, owner-only file and queue cases in the Factory service suite, and give existing marker and review fixtures trusted authors. Updated the delegated approvers file description and a new Factory intake trust inventory entry. README overview and onboarding are unchanged. Agents still act on GitHub as the owner, so this does not stop an agent misled into writing outside text as the owner, or a change between Triage's check and its label. Not installed: delivery needs a Host daemon install, and the charter change triggers the Mechanic's instructions review.
