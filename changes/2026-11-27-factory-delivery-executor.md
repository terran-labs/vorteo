### Maintenance

- Added the Lean Factory delivery executor: a daemon state machine that ships betas, promotions and rollbacks from the accepted commit's recipe without opening an agent session. Each run works through the release number report, the recipe's gates for its tier, the deploy step and the verify step, with a receipt for each. A failed gate stops the run before anything deploys. It survives a daemon restart in any state and never repeats a deploy on its own; a step whose outcome was lost waits for the owner to verify, rerun or abandon it. A promotion needs the owner's recorded approval of that exact beta, and Host steps need the merge gate's record for that commit. Release values reach commands only as environment variables, and step output stays out of the ledger. A failed beta is recorded as a failed release event, delivered releases carry their gate results, and callers can supply release notes before the deploy, which otherwise lists the batch's pull request titles. Nothing calls it yet, so behaviour is unchanged.
- Each deploy is bracketed by the default branch's head before and after. Every commit that landed in between must touch only the recipe's declared release records, or the run fails verification and names the offending commits. After verification, Factory commits only the rows its release tools appended to those records. It pushes them fast-forward only and records the commit on the delivery receipt. The daemon prepares a dedicated delivery worktree at the path the settings name: it creates it on first use, refuses an unrelated existing path, fetches, and detaches at the commit to run. It installs dependencies only when the lockfile changed, and tags betas locally when the recipe names a prefix. An owner pause cancels any beta that has not deployed and has nothing running.
- Added Host and Dev container step adapters. Each runs a step in its own session with output in a private file, so a deploy keeps running if the daemon stops. They record the process id and never signal it, and run only in a checkout verified to be at the commit the run prepared. Promotions and rollbacks prepare at the current default branch, which needs its own merge gate record.
- Added a draft Lean Factory configuration for Mira that wraps its existing ship and rollback tools and verifies releases the way Mira's release tool does.
