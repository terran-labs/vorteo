### Maintenance

- Added the Lean Factory delivery executor: a daemon state machine that ships betas, promotions and rollbacks from the accepted commit's recipe without opening an agent session. Each run works through the release number report, the recipe's gates for its tier, the deploy step and the verify step, with a receipt for each. A failed gate stops the run before anything deploys. It survives a daemon restart in any state and never repeats a deploy on its own; a step whose outcome was lost waits for the owner to verify, rerun or abandon it. A promotion needs the owner's recorded approval of that exact beta, and Host steps need the merge gate's record for that commit. Release values reach commands only as environment variables, and step output stays out of the ledger. A failed beta is recorded as a failed release event, delivered releases carry their gate results, and callers can supply release notes before the deploy, which otherwise lists the batch's pull request titles. Nothing calls it yet, so behaviour is unchanged.
- Each deploy is bracketed by the default branch's head before and after. Every commit that landed in between must touch only the recipe's declared release records, or the run fails verification and names the offending commits. After verification, Factory commits only the rows its release tools appended to those records. It pushes them fast-forward only and records the commit on the delivery receipt. The daemon prepares a delivery worktree from a private object pool in its own home, named by the settings, with links beside it that must point at exactly their configured directories. It builds the pool in a staging folder and renames it into place, talks only to the project's origin, never runs Git in the owner's checkout, and refuses any existing path or link it did not create. It detaches at the commit to run, installs dependencies only for betas and only when the lockfile changed, and tags betas locally when the recipe names a prefix. When the recipe declares its frozen artifacts, the daemon reads each one itself, executing nothing and following no symlink. It hashes every file and records every symlink by name and target, along with where the artifact's dependency link resolves and that directory's installed lockfile. A beta records this at verification. Every promotion and rollback compares it before deploying and again at verification, and is refused when the evidence is missing, the bytes changed or the dependencies changed. The digest is an unambiguous list of typed entries that includes empty directories. Special files are refused, every file is read only through a handle that is the inode the listing saw, and a directory replaced during the read refuses the evidence. Dependency evidence counts only when the link resolves to the Factory's own delivery checkout. Dependencies are detected, not frozen. A beta is also refused when its next version or release number already exists in the release tools' local records but not on the origin. The daemon records when it attempted the beta notice before handing it to the sender. A project may declare tag patterns to import and publish. The checkout imports matching origin tags without ever overwriting a local one. After a verified production promotion it publishes exactly the matching tags the release tool created during that run, atomically and without force. It never publishes milestone tags or moves a tag, and a refused push leaves the release delivered with the reason recorded. An owner pause cancels any beta that has not deployed and has nothing running.
- Added Host and Dev container step adapters. Each runs a step in its own session with output in a private file, so a deploy keeps running if the daemon stops. They record the process id and never signal it, and run only in a checkout verified to be at the commit the run prepared. Promotions and rollbacks prepare at the current default branch, which needs its own merge gate record.
- Added a draft Lean Factory configuration for Mira that wraps its existing ship and rollback tools and verifies releases the way Mira's release tool does.

## Maintenance review

The executor and adapters are covered by one focused test file with a fake process starter: restart at each state, no second deploy after an interrupted one, refused promotions and Host steps, hostile release values, gate failures, release numbers, notes, checkout verification, branch evidence, the records commit, the pause and the delivery worktree. The delivery worktree and the records commit also run against real Git, with a disposable clone and bare remote: an appended row is pushed fast-forward, and an edited row, a dirty source file, rows changed upstream, a stale expected head and an unrelated existing directory are all refused with the remote left unchanged. So are a link to another directory, a real directory in a link's place and a link target reached through another symlink. Tag publication pushes a new tag and refuses one the origin holds on another object, leaving the origin's tags unchanged, and the import refuses to retarget a local tag. Those runs found two defects the fakes hid: a misread first changed path, now read from NUL-separated names, and a records commit that could not see an expected head pushed after prepare, now fetched first. It is not wired into the reconcile loop, and the merge gate record, the owner approval path and Mira's real tools have not run through it.
