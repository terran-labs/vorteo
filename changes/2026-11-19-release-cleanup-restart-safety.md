### Fixes

- Coordinator restarts no longer cut a running Host release cleanup: settings changes, coordinator follow updates and custom domain changes are refused while one runs, and release upgrades and lab self-updates wait for it, at most 30 minutes. A cleanup that a restart does cut is marked interrupted at the next coordinator start, with what it removed and what it left.

## Maintenance review

The first real cleanup was cut six minutes in by a coordinator follow update, leaving one folder half deleted and its receipt at "running" for hours. Follow, settings and custom domain changes already share one restart check that refuses at request, approval and dispatch while other lifecycle work runs; the cleanup joins it, because those callers already retry and an approved restart should not wait on a deletion of unknown length. Release upgrades and lab self-updates restart the coordinator from inside an approved multi-step job right after their Host step starts a cleanup, so their coordinator step waits, bounded at 30 minutes, after which the cut is safe. Bootstrap coordinator requests and restarts from outside the coordinator are not held. At coordinator start, under the release root lock, the startup pass marks each `retention.json` left `running` as `interrupted`, with an `outcome` of removed folders and the state of each one not removed. Tests cover the shared refusal, the upgrade wait and its bound, the lab wait and the receipt repair; each fails when its check is removed. Documented in the installation reference. README overview and onboarding are unchanged. Not installed.

Review follow-up: the restart refusal applies only while a cleanup that renames and deletes runs, never for a dry or off run, and lapses 30 minutes after that cleanup started, with the lapse time in the message; `plutil` and the lock's `ps` call time out after two minutes and fail closed. The startup pass marks receipts only while holding the process's single cleanup slot: it skips marking when a cleanup already runs, and a cleanup that would start during the few milliseconds of marking is skipped with a receipt saying so, so a lock-free dry or off run's own receipt is never overwritten. The guard's cleanup view is now built by `coordinatorRestartState`, which the server uses, and a test drives a real dry run and a real run through the real start function against it. A dry run called without a plan listener now still reads its evidence.
