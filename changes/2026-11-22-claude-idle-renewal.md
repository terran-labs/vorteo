### Fixes

- A Claude subscription account that nothing on the Host is using no longer stays expired until its next use. Claude Code renews a sign-in only when a session starts or makes a request, so an idle account expired after eight hours and its copy in Dev reported "Claude is not connected" until someone used the account on the Host; on one installation that lasted about 42 hours. The daemon now renews a full sign-in about a minute after it expires unrenewed, by starting one Claude Code process with no prompt and letting it finish.

## Maintenance review

`claudeRenewalState` in the Claude provider's `model-discovery.ts` replaces the yes or no of `claudeRenewalDue`, which remains for the provider diagnostic and returns what it did before for every input: a full sign-in grant is `due` from ten minutes before its expiry, and `idle-expired` once it is a minute past expiry, which means no session renewed it in the five minutes Claude Code allows before expiry or in the minute after. Model discovery still starts no probe in either state and answers with its last models; for `idle-expired` it also starts an idle renewal apart from the refresh, so a canceled refresh cannot end it. The renewal takes the account's start slot as a session start does, checks again that the grant is still expired, and opens the same CLI as the discovery probe (no prompt, no saved session, no user hooks or MCP servers). It waits up to thirty seconds for the CLI to answer and up to ten for the stored grant to read renewed, reading the grant itself so that a sign-in erased by a rejected refresh token is reported as signed out and not as renewed. It then leaves the CLI alone for as long as the renewal lock is held, up to ninety seconds, ends its input and gives it five seconds to exit by itself before any stop. At provider shutdown those steps shorten to the ordinary stop wait, one second and a one second kill, about five seconds in the worst case, so a CLI caught mid-renewal by a shutdown can still be stopped. It runs once per account in ten minutes, and in an hour after an attempt that did not renew, and reports its outcome to the provider log. The CLI's models are kept as a discovery answer. Verified on the lab Host on 2026-11-22 against one full sign-in that had been expired for almost five hours: one Claude Code 2.1.321 process started in the probe's mode took the renewal lock 0.25 seconds after starting, saved the new sign-in within 0.7 seconds, opened no connection for a model request in its debug output and exited with status 0 when its input ended. That is one observation on one version. Limits: the renewal runs only when something asks the daemon for its model list, as a connected client or, on the lab Host, the coordinator's status poll does, so a daemon nobody talks to does not renew; an account whose refresh token the sign-in server rejects has its sign-in erased by the CLI a minute after expiry, where before that happened at its next session; whether a refresh that fails because the network is down, as just after the computer wakes, erases a sign-in is not verified (the 2.1.321 code read on 2026-11-13 erases on a rejected grant, and a session start in the same state would make the same request); a daemon that exits while the renewing CLI holds the lock can still lose the sign-in, as with any Claude Code process; the start slot is per process, so a session starting in the session host at the same moment is serialized only by Claude Code's own lock; environments holding access-only copies start nothing, since they have no refresh token. The coordinator's "expiring without a successful refresh" warning is unchanged and still repeats until the renewal lands. Codex is not covered: its sign-ins are per environment, with an optional coordinator refresh, and need their own change. Two tests cover the minute of grace, the renewal surviving a canceled refresh, the single attempt, the next refresh being served by its answer, and the CLI being left alone while the renewal lock is held and then exiting by itself; each fails when the behaviour it covers is removed. The subscription accounts entry in the customizations inventory (current copy) and the providers guide are updated. README overview and onboarding are unchanged. Not installed.
