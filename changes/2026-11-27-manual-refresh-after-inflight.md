### Fixes

- Refreshing a workspace right after switching its branch shows the new branch, and so does the state shown after a branch switch, create, rename, discard, stash, commit, merge, pull, push or pull request action. It could keep the old one when the refresh arrived while the daemon was still reading the workspace, for example just after the project was opened. Refs #675.

## Maintenance review

A forced manual refresh (`checkout.refresh`) that arrived while another forced refresh was in flight, such as the one `workspace.create` starts with reason `open_project`, joined it and returned its pre-checkout snapshot. Nothing re-read afterwards, so the workspace kept its old branch until its next Git event. The handler now passes `afterInFlight`, which queues a replay after the running refresh. Found with an instrumented run of `command-center-workspaces.spec.ts:154`: on the e2e worker daemon, the first refresh right after the checkout returned and kept `main`, and a second refresh three seconds later read the new branch. The coalescing and the opening refresh both date from April. The reviewer's reading of the code, not verified by a run: before #686 the checkout's own HEAD watcher event queued a replay even for an idle workspace, so the stale join healed within about two seconds; #686 deferred that event for idle workspaces, and #715 restores it only where the watcher delivers. The workspace Git service suite gains a case that fails without `afterInFlight`, and the checkout session case asserts the handler requests it. Updated the workspace Git fetch entry in the inventory. README overview and onboarding are unchanged. Git mutations (`notifyGitMutation`) also refresh with `afterInFlight`: switch, create and rename branch, discard, stash, commit, merge, pull, push, pull request actions and worktree creation. Each is an explicit action, and the option adds at most one extra refresh, only when another is already running. The session suite expectations for those refreshes and for the manual refresh now include the option; the first commit missed the manual refresh one.
